# ADR 0002: Go Clean-Slate Rewrite

- Status: Accepted
- Date: 2026-07-26
- Supersedes in part: ADR 0001 (decisions 1, 3, 5, and 6)

## Context

ADR 0001 planned a Go port that lived alongside the Rust implementation in a
`go/` subtree, with golden fixtures generated by the Rust binaries, a parity
harness diffing the two collectors against one database, and a mechanically
enforced freeze on the Rust tree. Every one of those mechanisms exists to manage
two live trees at once.

Two things changed the calculation.

The first is that parity turned out to be the wrong goal. The Rust tree's
on-disk formats were never specified independently of the code that wrote them:
the encrypted envelope was documented by reading the Rust source, and the schema
document was whatever `serde` produced from the model types. Holding a new
implementation to that is holding it to a set of accidents. Several of those
accidents are ones the Go tree should not reproduce -- a validated minimum with no
maximum on the Argon2id cost parameters, a compiled-pattern cache inside a
configuration struct that deserialization skipped, and a placeholder adapter for
an engine no pure-Rust driver could reach.

The second is that the Rust tree had no released consumers to be compatible
with. dbsurveyor has not shipped a v1. There is no artifact in the field that a
Go implementation must be able to read, so backward compatibility buys nothing
and costs the entire parity apparatus.

## Decision

1. **The Go implementation is a clean-slate rewrite at the repository root.**
   The `go/` subtree from ADR 0001 decision 1 is not used. There is one tree.

2. **The Rust implementation is removed from the default branch** and preserved
   in full on the `rust-final` branch. Nothing in the Go tree is obliged to read
   a Rust-era artifact.

3. **The on-disk formats are specified fresh** under `docs/formats/`, with the
   Go implementation as the reference. The specifications are held to the code
   by tests: the published JSON Schemas are generated from the Go types, and the
   encrypted-envelope specification publishes a complete envelope in hex that a
   test reproduces from injected salt and nonce bytes.

4. **No parity harness and no Rust-generated fixtures.** Golden files in this
   tree are Go-authored: they record what this implementation produces so that a
   change is a visible diff, not a claim of byte compatibility with anything.

5. **Versioning is unchanged from ADR 0001 decision 4.** The Rust line is frozen
   at v0.1.x and the first Go release is v0.2.0. The v1.0.0 signal is still
   reserved for after the implementation has survived real operator use.

| 1 | Go lives in a `go/` subtree | Superseded: the Go tree is the repository root |

## Consequences

- **Positive.** One toolchain, one CI configuration, one set of conventions. The
  formats are specified rather than reverse-engineered, and each specification
  is enforced by a test rather than by a reviewer's memory. Several defects
  carried in the Rust tree are designed out rather than reproduced -- the
  unbounded Argon2id cost, the deserialization-skipped pattern cache, and the
  placeholder adapter are each recorded in `GOTCHAS.md` alongside what replaced
  them.

- **Negative.** There is no automated evidence that the Go tree collects the
  same schema the Rust tree did. That evidence would have come from the parity
  harness, and this decision gives it up deliberately: the Rust output was never
  a specification, and treating it as one would have carried its accidents
  forward. What replaces it is per-engine integration tests against real
  database containers, which check the Go tree against the *engines* rather than
  against the previous implementation.

- **Negative.** Anyone holding an artifact produced by a Rust-era build cannot
  read it with a Go build. There are no released consumers, so this affects
  development artifacts only; `rust-final` remains buildable for anyone who
  needs one.

- **Follow-up.** `docs/go-port-migration-strategy.md` described the two-tree
  transition and is retired. The database-behavior entries in `GOTCHAS.md` were
  carried forward and re-validated against the Go adapters; where a carried entry
  turned out to be wrong, the correction is stated rather than the original left
  standing.
